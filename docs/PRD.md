# 经期状态助手 · PRD v0.4

> 面向个人使用的「身体状态导航系统」：基于 Apple 健康中的经期记录，判断当前周期阶段，给出状态解释与行动/饮食/运动建议，长期沉淀个人「周期-状态」规律。
>
> 变更记录：
> - v0.1（原始构思）：ChatGPT/Codex Agent 起步
> - v0.2（2026-11-06）：技术路线改为 **本地优先 PWA**；MVP 智能改为**规则引擎**（不依赖联网 LLM）；每日输入大幅减负；明确阶段算法与异常提醒规则
> - v0.3（2026-11-06）：**去 Agent 化**——产品形态确定为手机个人工具（"Agent"只是早期构思时的说法）；**经期数据以 Apple 健康为唯一权威来源**，本工具不重复做经期记录，只做阶段解读、状态打卡与建议；健康数据同步方案待定
> - v0.4（2026-11-06）：**同步方向反转**——经期记录入口改到本工具（记录时顺手勾选症状），经快捷指令「记录健康样本」写入 Apple 健康；健康作为自动同步的仓库，其周期跟踪/预测照常工作；首次使用从健康反向导入历史做初始化；绝不双录

## 1. 目标与边界

### 目标
- 3 秒内看到「我今天处于哪个阶段、适合做什么、注意什么」
- 10 秒内完成每日状态打卡
- 1-3 个月后能看到自己的周期规律（哪几天状态好、哪几天容易崩）
- **设计红线：绝不双录——经期只记一次（入口在本工具，可顺手记症状），一键同步写入 Apple 健康**

### 非目标（重要）
- ❌ 不做疾病诊断、不替代医生、不推荐药物或补剂剂量
- ❌ 不做受孕窗口预测用于避孕/备孕决策（MVP 明确声明：阶段估算不能作为避孕或备孕依据）
- ❌ 不做社交、社区、账号体系
- ❌ MVP 不做推送通知（PWA 在 iOS 上配置成本高，先用"每天主动打开"的习惯）

### 安全边界（异常时提示就医）
出现以下情况，界面固定提示「建议咨询医生」：
- 经期持续 > 8 天
- 周期 < 21 天或 > 35 天（连续出现）
- 本次周期比个人平均值偏离 > 7 天
- 用户主动记录"剧烈疼痛"或"出血量异常大"
- 严重痛经、贫血风险、备孕、怀孕、激素药物、PCOS 等情况在文案中统一引导就医

## 2. 技术路线（已定）

| 决策 | 结论 | 理由 |
|------|------|------|
| 形态 | **PWA（单页 HTML + localStorage）** | 零成本；iPhone「添加到主屏幕」即用；数据不出本机 |
| 智能层 | **规则引擎**（阶段算法 + 阶段×症状建议文案表） | 确定性、离线可用、隐私最好；不接联网 LLM |
| 部署 | **GitHub Pages（已定，v0.4 实施）**：https://panpanni0520-bot.github.io/cycle-agent/ —— 页面公开但不含任何数据，数据全在手机本地。原计划的 Artifact 发布因登录方式限制不可用，已放弃 | 免费、URL 稳定、随时随地可用，也是将来 PWA 化的基础 |
| 数据 | 全部 localStorage 存本机，支持导出/导入 JSON 备份 | 无账号、无服务器、无泄漏面 |
| 经期数据源 | **本工具是记录入口（v0.4 已定）**：工具内记录经期开始/症状 → 经 shortcuts:// 唤起快捷指令「记录健康样本」写入 Apple 健康；首次使用从健康反向导入一次历史记录做初始化 | 快捷指令可读也可写健康样本，双方向都走 shortcuts:// 桥接；用户永远只记一次 |
| 未来升级路径 | 快捷指令同步健康数据 → 可视化日历 → （可选）接 LLM 做规律分析 → 原生 App | 与原始构思的五阶段对应，但顺序按成本重排 |

## 3. 用户与场景

**唯一用户**：我自己（个人工具，不考虑他人使用）。

**核心场景**：
1. 早晨打开 → 看今日阶段 + 建议 → 关掉（3 秒）
2. 晚上（或随手）→ 打卡今日精力/情绪/不适（10 秒）
3. 月经来了 → 在本工具点「月经来了」（可顺手勾选症状）→ 一键同步写入 Apple 健康 → 自动重算周期
4. 每月回顾 → 看本月状态曲线与规律小结

## 4. 核心算法：周期阶段识别

**输入（初始化一次）**：最近一次月经开始日期（必填）；历史 2-6 次开始日期（可选，用于算平均周期与波动）。

**参数自动维护**：
- 平均周期长度 L：由历史开始日期自动计算，默认 28 天；每次新月经开始时更新
- 经期长度 M：默认 5 天，可由历史记录修正
- 周期波动 σ：历史周期长度的极差；σ > 7 天时所有预测标注「仅供参考」

**阶段判定**（cd = 今天 − 本次月经第 1 天 + 1，即周期第几天）：
- 预计排卵日 ovu = L − 14（黄体期相对固定约 14 天，比卵泡期稳定）
- 月经期：cd ≤ M
- 卵泡期：M < cd < ovu − 1
- 排卵期：ovu − 1 ≤ cd ≤ ovu + 1（前后各 1 天窗口）
- 黄体期：cd > ovu + 1
- cd > L + 7 → 不猜阶段，直接提示「可能漏记或周期异常」

## 5. MVP 功能（第一版做这些，别的不做）

### F1 今日面板（打开即见）
- 当前阶段 + 周期第几天 + 下一阶段预计时间
- 今日一句话状态解释（规则文案）
- 今日「适合 / 不适合」各 2-3 条
- 饮食关注 2-3 条、运动建议 1 条、休息提醒 1 条
- 波动大时显示置信度提示

### F2 快速打卡（10 秒，自适应设计·已定）
- 3 个必选项（各 3 档点选）：精力（高/中/低）、情绪（稳/平/差）、身体不适（无/轻/重）
- 自适应展开：选了「有不适」才展开症状勾选（腹痛/头痛/疲惫/失眠/食欲变化/皮肤）与一句话备注；正常日子永远只点 3 下
- 「月经来了」快捷记录（首页常驻）：**核心字段 = 开始日期 + 结束日期**（用户最低要求：起止时间必须记准）。开始时一键记开始日，结束后补记结束日；症状为可选项 → 唤起快捷指令按起止日期逐天写入 Apple 健康；症状映射到健康的经期症状类型（腹痛→腹部绞痛、头痛→头痛、疲惫→疲劳、皮肤→痤疮等，映射不了的仅存本地）；首次使用时从健康反向导入历史经期做初始化
- 经期进行中若未填结束日，首页持续显示「经期第 N 天 · 结束了点这里」，确保结束时间不漏记

### F3 建议引擎（规则表，本地文案库）
- 维度：4 个阶段 × 3 档精力/情绪/不适 → 组合文案
- 内容覆盖：工作建议（高认知任务/深度工作/轻任务/复盘整理）、社交建议、运动建议、营养关注（只给关注点不给剂量）
- 月经期：铁、蛋白质、温热饮食、补水；卵泡期：蛋白质、复合碳水、蔬果；排卵期：抗氧化食物、补水、规律作息；黄体期：镁、钙、B 族、复合碳水、减少咖啡因与高糖波动

### F4 历史与备份
- 月经开始日期列表 + 快速修正（记错了能改）
- 打卡记录列表
- 导出/导入 JSON

### 明确不做（MVP）
- 日历可视化、统计图表 → v0.3
- 推送提醒 → 待定
- LLM 对话 → 远期

## 7. 文案基调

- 像一位了解自己的朋友，不像医生，不像教练
- 给「许可」而非「命令」：低能量日说"今天适合放低要求"，而非"你必须休息"
- 所有建议带一句「为什么」（基于阶段），帮用户建立自己的直觉

---

## 8. 成功指标（自用版）

- 连续使用 4 周不缺卡 > 60% 天数 → 说明打卡负担足够低
- 2 个周期后，回看时认为「阶段判断大体准」→ 算法可信
- 至少 1 次因为建议调整了当日安排 → 建议有实际价值
